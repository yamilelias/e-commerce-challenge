# Backend foundation (BE-01)

- Status: BE-01 through BE-02d implemented and verified in a PHP container; Docker Compose end-to-end integration remains.
- Public route: `GET /api/v1/health` in `apps/api/src/Controller/Api/V1/HealthController.php` executes `SELECT 1` through Doctrine DBAL and returns the frozen `{data:{status,database}}` payload or a 503 error envelope.
- API entry points: `apps/api/public/index.php` boots `apps/api/src/Kernel.php`; `apps/api/bin/console` exposes Symfony CLI commands. Attribute routes are loaded by `apps/api/config/routes.yaml`. Unhandled API exceptions are mapped to generic JSON by `apps/api/src/Http/ApiExceptionSubscriber.php`.
- Persistence: `apps/api/migrations/Version20261015000000.php` creates `categories`, `products`, `orders`, and `order_items` with unique indexes, foreign keys, CHECK constraints, and the frozen `request_fingerprint` and `receipt_token_hash` columns. Matching Doctrine mapping classes are in `apps/api/src/Entity/{Category,Product,Order,OrderItem}.php`. `apps/api/src/Database/SqliteConnection.php` enables foreign keys and a 5-second busy timeout per SQLite connection; Doctrine wiring is in `apps/api/config/packages/doctrine.yaml`.
- Runtime: Requires PHP 8.3+, PDO SQLite, mbstring, installed Composer dependencies, `DATABASE_URL`, `APP_SECRET`, `SESSION_COOKIE_SECURE`, and writable `/data/sessions`; DevOps owns container configuration. `apps/api/composer.json` and `apps/api/composer.lock` pin dependencies for PHP 8.3.
- Verification: Composer install, PHP lint, PHPUnit (17 tests, 89 assertions), Symfony route list, a throwaway SQLite migration, Doctrine schema validation, and HTTP kernel health/session/create/duplicate/import/checkout/replay/receipt flows passed in a PHP 8.5 container with dependency resolution targeted at PHP 8.3. Python SQLite also rejected duplicate SKU, nonpositive price, and missing category FK. Docker Compose end-to-end remains pending integration.
- BE-02a source: `GET /api/v1/categories`, `GET /api/v1/products`, and `GET /api/v1/products/{id}` are handled by `apps/api/src/Controller/Api/V1/CatalogController.php`. `apps/api/src/Service/ProductService.php` queries active catalog rows with literal substring search, category/sort/pagination, and maps frozen Product DTOs. `apps/api/src/Service/ProductInput.php` normalizes and validates product write/import fields; ProductService also contains create/update/soft-delete methods. `apps/api/src/Http/ApiProblem.php` carries expected API failures to the exception subscriber. Unit and SQLite service tests in `apps/api/tests/` pass.
- BE-02b source: `GET /api/v1/admin/session`, `POST /api/v1/admin/login`, and `POST /api/v1/admin/logout` are handled by `apps/api/src/Controller/Api/V1/AdminSessionController.php` using `apps/api/src/Security/AdminSession.php`. The service checks session authentication, session-bound CSRF token, Origin, environment credentials, and rotates session/token at login. `GET /api/v1/admin/products*` and `POST/PATCH/DELETE /api/v1/products*` are handled by `apps/api/src/Controller/Api/V1/AdminProductController.php` behind the same guard. `apps/api/src/Http/JsonInput.php` enforces JSON object input and body size. Unit tests in `apps/api/tests/Unit/AdminSessionTest.php` pass, while full proxied cookie flow remains pending integration.
- BE-02c source: `POST /api/v1/products/import` in `apps/api/src/Controller/Api/V1/ImportController.php` enforces administrator session/CSRF, multipart `file`, `.csv`, and 2 MiB limits. `apps/api/src/Command/SeedProductsCommand.php` exposes `app:products:seed --file=...`. Both call `apps/api/src/Service/CsvProductImporter.php`, which preflights UTF-8/header/quote syntax, parses logical CSV records, reuses `ProductInput` and `ProductService`, creates valid products only, and returns capped row issues. `apps/api/tests/Integration/CsvProductImporterTest.php` checks multiline row numbering, dirty rows, invalid header, and reseed behavior. The bundled 97-row CSV inserted 85, skipped 5, rejected 7 on first run and inserted 0, skipped 90, rejected 7 on second run against disposable SQLite.
- BE-02d source: `POST /api/v1/orders` and token-protected `GET /api/v1/orders/{reference}` are handled by `apps/api/src/Controller/Api/V1/OrderController.php`. `apps/api/src/Service/CheckoutService.php` validates and fingerprints canonical guest requests, uses SQLite `BEGIN IMMEDIATE` and conditional stock decrements, stores paid orders and line snapshots in one transaction, and returns stable idempotent replays. `apps/api/src/Service/ReceiptTokenService.php` derives a bearer token from the checkout UUID and `RECEIPT_SECRET`, while the database stores only its hash. `apps/api/src/Service/FakePaymentGateway.php` provides deterministic success. `apps/api/tests/Integration/CheckoutServiceTest.php` covers replay/conflict, rollback, receipt access, and a two-process final-unit race using `apps/api/tests/Fixtures/CheckoutWorker.php`.

See `docs/02-ARCHITECTURE.md`, `docs/03-BACKEND.md`, and `docs/04-API.md` for the frozen contracts.
