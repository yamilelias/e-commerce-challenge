# Products page redesign

- `/products` is composed by `apps/web/src/app/products/page.tsx` and `CatalogPageClient.tsx`. The client keeps URL-backed search, category, sort, and page state; `apps/web/src/components/catalog/CatalogResults.tsx` fetches the matching page and wraps editorial `ProductCard` entries in the existing `Reveal` motion component. `ProductPages.module.css` supplies the photo hero, responsive category strip, catalog grid, and page styles.
- `/products/[id]` is composed by `apps/web/src/app/products/[id]/page.tsx` and `ProductDetail.tsx`. It reads the public detail API, displays the ordered `images` array with selectable thumbnails and credit for the visible image, adds the selected quantity through `CartProvider.add`, and requests same-category products for the related section. It handles missing, loading, and retryable error states.
- `apps/web/src/components/products/ProductCard.tsx`, `ProductImage.tsx`, and `ProductCard.module.css` crossfade the first alternate on catalog card hover or keyboard focus. The base image stays visible if the alternate fails; existing homepage cards use the default variant.
- `apps/web/src/components/catalog/ContactSection.tsx` appears before the shared footer on both products routes. Its button uses `mailto:no-reply@fieldnform.com`. The hero and contact section use direct Commons thumbnail URLs, show creator/source/license credits, and have forest-color backgrounds if remote media fails.
- `apps/web/src/lib/api/types.ts` declares the `ProductPhoto` shape and ordered `Product.images`. The API and database implementation are mapped in [`backend.md`](backend.md), and the authoritative response is in [`../../docs/04-API.md`](../../docs/04-API.md).
