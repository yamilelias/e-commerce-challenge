# Infrastructure structure

- `compose.yaml` defines `api` and `web`. Only `web` publishes `127.0.0.1:${WEB_PORT:-3000}:3000`. `web` calls `api` at `http://api:8000` and waits for its health check. The `ecommerce_data` named volume mounts at `/data` in `api` only.
- `apps/api/Dockerfile` builds the PHP 8.3 FrankenPHP API image from the repository root context. It copies the unchanged fixture to `/app/data/products.csv` and the curated URL catalog to `/app/data/product-images.json` in test/runtime stages; `apps/api/Dockerfile.dockerignore` excludes private env files and local build/database outputs.
- `infra/docker/api/entrypoint.sh` validates required variables, prepares `/data/sessions` and `/app/var`, and drops to `www-data`. `infra/docker/api/start.sh` runs Doctrine migrations, `app:products:seed --file=/app/data/products.csv`, and `app:products:images --file=/app/data/product-images.json` before starting FrankenPHP using `infra/docker/api/Caddyfile` on port 8000. The image creates an empty `/app/.env` for Symfony Runtime while keeping private values in Compose environment variables. `infra/docker/api/health.php` checks the DB-aware `/api/v1/health` endpoint for HTTP 200 and the expected JSON readiness fields.
- `apps/web/Dockerfile` builds Next.js standalone output with Node 22 and runs `server.js` as `node`; `apps/web/Dockerfile.dockerignore` excludes private files and local build outputs. `compose.yaml` supplies server-only `API_INTERNAL_URL=http://api:8000` and checks the public root route for HTTP success.
- `.env.example` lists local configuration inputs. Real `.env` values are untracked. Backend owns the health route, migration and seed command; frontend owns the `/api/v1/*` proxy. The proxied health route works in the isolated Compose runtime.

Verification: On 2026-10-16, `WEB_PORT=3300 PUBLIC_ORIGIN=http://localhost:3300 docker compose -p ecommerce-inf02 up --build -d` built both images and started both healthy. Browser-facing `/api/v1/health` returned HTTP 200 with `status=ok` and `database=ok`; migration status showed one applied migration and SQLite contained 85 products. `docker compose -p ecommerce-inf02 down` followed by `up -d` kept 85 products; repeat seed inserted 0, skipped 90, rejected 7. The test project uses its own named volume and remains separate from the default project.
